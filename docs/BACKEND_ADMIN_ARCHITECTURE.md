# 后台管理架构

后台只保留六个业务域：用户、伴侣、对话与 AI、创建与素材、商城、网站设置。

## 管理入口

- `/admin`：兼容入口，自动跳转到 `/admin/control`。
- `/admin/control`：系统总控，查看状态并进入管理或创建流程。
- `/api/admin/control-center`：只读聚合接口，统一返回模块状态与核心数量。
- `src/lib/admin/systems.ts`：后台业务域的单一事实源。

## 合并规则

- 积分、代币、会员统一归入用户管理。
- 审核、媒体、角色卡和人设资料统一归入伴侣管理。
- 模型、AI 方案、服务健康和供应商路由统一归入对话与 AI。
- 工作台、生成预设、模型 LoRA、捏脸预览和公共资产统一归入创建与素材。
- 商品、礼物和加密支付统一归入商城。
- 首页模块、页面、导航、广告和全站配置统一归入网站设置。

旧路径继续保留，以兼容书签与内部链接，但不再作为侧栏一级入口。

## 开发约束

1. 新后台能力必须先归入现有业务域，确实无法归类时才新增一级系统。
2. API 只负责鉴权、参数解析和响应；复杂业务下沉到 `src/lib/<domain>/`。
3. 管理 API 必须使用 `requireAdmin()`；写操作由统一限流保护。
4. 客户端只通过 `authedFetch()` 访问 BFF，不直接使用 service role。
5. 删除采用归档或停用优先；物理删除只允许 superadmin。
6. 聚合统计失败时单模块降级，不应导致整个后台不可用。
